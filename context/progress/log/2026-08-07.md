## 워크플로 8단계 전면 재작성 + B트랙 실연결 (Claude Code)

`context/knowledge/scenario-walkthrough.md`(사용자 관점 8단계, 2026-08-06 작성)와 실제 코드 구조가
많이 다르다는 지적에 따라, 백엔드를 그 시나리오 기준으로 다시 짰다.

- `workflow.py`: `State`/`EventType`를 waiting/greeting/deciding/guiding/capturing/previewing/
  asking/farewell 8개로 교체. 옛 BOOTING/READY/REPOSITIONING/GUIDING/VERIFYING/CAPTURING/REVIEWING
  구조와 VLM `Verifier`(`verification.py`)는 제거 — 정렬 확인은 VLM이 아니라 B트랙 웹캠 신호로 대체.
  `WorkflowContext.photo_url`(단일) → `photos: list[str]`(버스트 3장)로 교체.
- `coordinator.py`: 배경 이펙트를 새 상태에 맞게 재작성.
  - `greeting`/`previewing`/`farewell` 진입 시 타이머로 자동 다음 이벤트 emit.
  - `capturing` 진입 시 `burst_poses_for_template()`(robot.py에 추가, 전신/상반신/제품 3포즈)로
    로봇을 옮기며 매 포즈마다 실제 `capture.capture()` 호출, 끝나면 `BURST_COMPLETE`.
  - `_sense_loop()` 신설: `person_sensor`가 있으면 매 `sense_interval`마다 폴링해서 `waiting`일 때
    `is_approaching()`이면 `PERSON_APPROACHED`, `guiding`일 때 `is_positioned()`이면
    `POSITION_REACHED`를 자동 emit — B트랙(`perception.py`)이 처음으로 워크플로에 실제 연결됨.
- `perception.py`: `WebcamFrameSource` 추가 — cv2 웹캠 읽기가 블로킹이라 별도 스레드에서 최신
  프레임만 들고 있다가 비동기 sense 루프에 넘겨줌.
- `app.py`/`config.py`: `runtime.person_sensor`(fake/mediapipe), `camera_index`,
  `sense_interval`/`greeting_seconds`/`preview_seconds`/`farewell_seconds` 설정 추가.
  `config/local-demo-no-robot.yaml` 신설 — `robot: fake`라서 RViz 없이도 1~4단계(웹캠 감지+iPad UI)를
  노트북 하나로 검증 가능(로봇은 5단계 버스트 촬영에서만 실제로 움직임).
- `web.py`: 새 엔드포인트 `POST /api/capture-started`(template_id 필요)/`decline`/`replay`/`liked`/
  `reset`. `/face`, `/guide`는 이제 Codex가 만든 `face-mock.html`/`guide-mock.html`을 서빙(옛
  `face.html`/`guide.html`은 라우트에서 제거, 파일은 아직 남겨둠).
- 테스트 전면 재작성(`test_workflow.py`, `test_fake_scenario.py`, `test_web.py`) — 이 과정에서
  `wait_for_state()`가 "이미 그 상태에 있는 채로 호출되면 즉시 반환"하는 성질 때문에, 같은 상태를
  왕복하는 전이(예: asking→previewing→asking replay)를 기다릴 때는 `wait_for_revision()`으로 먼저

  FastAPI `TestClient`에서 코디네이터에 직접 이벤트를 넣어야 할 때는 `client.portal.call(...)`로

  항상 정상 로드된다는 것도 확인 — 사용자가 보던 건 그 전 코드가 캐시된 옛날 탭이었을 가능성이 큼.

## 카운트다운 음성("3","2","1") + 촬영 전 "손 들어 준비완료" 대기 (Claude Code)

- **카운트다운 캐시 버그**: 사용자가 보고한 "카운트다운 안 됨"은 코드 문제가 아니라 `/guide` 탭이
  카운트다운 기능 추가 전 `mock.js`를 계속 물고 있던 스테일 캐시였음(기존 확인된 패턴과 동일).
  탭을 새로 열자 정상 동작 확인.
- **카운트다운 음성**: face 페이지가 `context.countdown` 변화를 감지해 매 틱마다 "3"/"2"/"1"을
  `speakCaption()`으로 읽어줌 (`web/mock.js` `updateData()`). `speakCaption`이 매번 `cancelSpeech()`로
  이전 발화를 취소하므로 0.7초 간격 틱과 자연스럽게 겹침 없이 이어짐.
- **촬영 전 "손 들어 준비완료" 대기 단계** 신설: 정위치 도달(`POSITION_REACHED`) 직후, 3-2-1
  카운트다운을 바로 시작하지 않고 사람이 손을 들 때까지 기다리는 단계를 추가.
  - `perception.py`: `PersonSignal.hand_raised` 필드 추가. `MediaPipePersonSensor.sense()`가
    BlazePose 랜드마크(손목 15/16, 어깨 11/12)로 손목이 어깨보다 위(더 작은 y)에 있으면
    `hand_raised=True`. `is_ready_signal(signal)` 헬퍼 추가.
  - `workflow.py`: `WorkflowContext.awaiting_ready: bool` 추가, 리셋 번들에도 포함.
  - `coordinator.py`: `_capture_burst()`가 카운트다운 전에 `_wait_until_ready()`를 호출.
    `person_sensor`가 없으면(테스트/시뮬레이션) 즉시 통과. 있으면 `awaiting_ready=True`로 패치하고
    `asyncio.Event`를 기다림 — `_sense_loop()`가 CAPTURING 중 `awaiting_ready`이고
    `is_ready_signal`이면 이벤트를 set. `ready_timeout_seconds`(기본 12초) 지나면 손을 못 들어도
    자동 진행 (fail-safe, 무한 대기 방지).
  - 프런트(`guide-mock.html`/`mock.css`/`mock.js`): burst 씬에 `#ready-overlay`(🙌 + "준비되시면
    손을 들어주세요") 추가. `currentCaption()`이 `awaiting_ready`일 때 이 문구로 캡션 교체, face
